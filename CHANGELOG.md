# Changelog

All notable changes to JARVIS AI are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project aims to
use [semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Web hologram face** (`JarvisAI/assets/holo/face/`): an interactive HTML/CSS/JS
  projection built from Bihansa's real portrait — 478 Face Mesh landmarks measured
  on the photo drive the wireframe, eye tracking and feature rings; the cut-out is
  graded as a pink projection with a rim light and fibre-optic hair; the hair is
  split at the parting into two independently swaying locks, and 236 silhouette
  filaments plus a projector base, telemetry HUD, voice-reactive breathing and
  pointer parallax complete the scene. Assets are generated by
  `JarvisAI/tools/build_holo_face.py` (offline: MediaPipe + OpenCV only) and ship
  as ~390 KB of WebP. See `JarvisAI/assets/holo/face/README.md`.

- **HUD is clean by default**: the autonomous surfaces (dashboard card, `◉`
  rail button, menu entries) are opt-in via `autonomous_ui_enabled` /
  `JARVIS_AUTONOMOUS_UI=1`. With the flag off the HUD is exactly as it was, and
  `test_hud_stays_clean_while_the_ui_flag_is_off` enforces it. The minimised
  island is not gated: it also carries battery, health and hologram state.
- **RAM profiler** (`JarvisAI/tools/profile_ram.py`, adopted from PR #143): samples
  the JARVIS process tree (RSS, USS, CPU, system-available RAM) into CSV with
  `--label`/`--append`, so idle / voice / screen / hologram runs can be compared on
  the 4 GB target machine. Sampling core is split into testable helpers.
- **Lazy Qt WebEngine** (`JarvisAI/core/qt_webengine.py`): Chromium is imported on
  first use instead of with the UI package. `import ui` no longer pulls the Earth
  globe, the document workspace or `PyQt6.QtWebEngine*` — measured in the sandbox
  as 137 ms/69 MB → 109 ms/49 MB, and `import ui.hud_main` 164 ms/62 MB → 150 ms/58 MB.
  The WebEngine path itself is unchanged; it loads when the legacy immersive view is
  actually constructed.
- **`docs/CLOUD_FIRST_RAM_AUDIT.md`** — evidence-based audit (what was measured,
  what was not, what needs the Windows laptop), including the open playback-queue and
  cloud-scheduler questions.
- Import-boundary regression tests (`tests/test_lazy_ui_imports.py`) that fail if the
  HUD import starts dragging in Chromium, OpenCV or the WebEngine panels again.
- **Autonomous task engine** (`JarvisAI/agent/`): validated planning (model or
  deterministic), bounded execution with retries/backoff/deadlines/loop
  detection, resumable JSON persistence plus an fsynced journal, pause/resume/
  cancel, and a final report. New `autonomous_task` voice tool (NON_BLOCKING),
  per-step risk classification, and approval through the existing confirmation
  gate.
- **Screen vision and computer use**: on-demand capture with coordinate mapping
  and buffer release, local OCR, Gemini/OpenAI vision with explicit uncertainty,
  accessibility-tree lookup, and validated named-target desktop actions with
  dry-run and post-action re-observation.
- **UI**: live autonomous-task card on the Bento dashboard, HUD menu/rail entry
  with an always-available STOP, and a compact Dynamic-Island status widget shown
  when the HUD is minimised. The hologram home screen is unchanged.
- `docs/AUTONOMOUS_AGENT.md` — configuration, security model, step kinds,
  tests and known limitations.
- Six new test modules (`test_agent_core/runner/screen/voice/integration/ui.py`)
  covering state transitions, persistence/resume, retries and budgets,
  cancellation, policy boundaries, vision/OCR fallbacks, computer-use validation,
  voice routing and the Qt surfaces.
- **Holographic command centre** (`docs/HOLOGRAPHIC_UI_UPGRADE.md`). The central
  hologram is now a real copper/amber wireframe *face* with a dome crown, tapered
  jaw, eye sockets, nose ridge and mouth crease — with hidden surfaces culled and
  a three-quarter gaze instead of an endless spin — and it clears to the HUD
  backdrop so it no longer floats inside a black rectangle. The status orb and
  the small "quantum heart" are docked together beneath the face, with a real
  filament from the heart to the chin.
- **Task-panel producers** (`core/task_sources.py`): the HUD's glass panels are
  no longer limited to voice commands. A `TaskSourceRegistry` polls the pending
  reminder (`memory.prospective_memory`) and Steam's own manifest state
  (`actions/game_updater`) and hands them to
  `TaskPanelManager.sync_sources()`, which opens, updates in place, and retires
  producer cards without touching command panels. A producer that raises is
  reported as *unavailable*, never as "nothing to show"; a dismissed card stays
  closed until its producer stops reporting the fact.
- **Real music transport** (`core/media_transport.py`): the music panel's
  play/pause/previous/next buttons now send the OS media keys. The buttons are
  drawn only when a key can actually be delivered, the play/pause glyph flips only
  after a press succeeds, and a successful music command opens one persistent
  `media:now` card. Deliberately not routed through `spotify_control`, which
  would launch Spotify from a panel showing any other player.
- **Battery-threshold settings UI** (`ui/panels/battery_settings.py`,
  `core/battery_settings.py`): *BATTERY THRESHOLDS* in the right dropdown edits
  `battery/fifty|low|critical|full`, validates the ordering before saving, and
  moves the adaptive-performance tiers to the same numbers. Junk or broken
  settings still degrade to the documented defaults.
- **Responsive HUD chrome** (`core/hud_layout.py`): the left rail (44 → 38 → 32
  px) and the right dropdown (300 px, capped at 34 % of the width, floor 208 px)
  now follow the window instead of being pinned to constants; the window's
  minimum size is 860×620 so the rules are reachable. Also fixes the dropdown
  opening as a 30 px empty strip: as a free-floating child it never received a
  height until it was sized explicitly.
- **`core/hologram_theme.py`** — one palette shared by every renderer.
  `JARVIS_PALETTE` is copper/amber, `BIHANSA_PALETTE` is rose pink, per-state
  accents sit on top of the persona instead of replacing it, and
  `VisualPreferences` persists glow, reduced motion, charging effects and the
  battery-saver toggle through `QSettings`.
- **`core/system_status.py`** — edge-triggered battery monitor (a machine with no
  sensor reports *unavailable*, never 0 %), subsystem health monitor with
  recovery notices, `AdaptivePerformance` that picks a render budget from battery
  + CPU load with hysteresis, and a deduplicated, bounded notification centre.
- **`core/subsystem_probes.py`** — real microphone / speaker / network / provider
  probes that run in one daemon thread, so the 5-second HUD tick never blocks on
  DNS. `JARVIS_DISABLE_SUBSYSTEM_PROBES=1` keeps tests offline.
- **`ui/task_panels.py`** — context-aware glass task panels. Controls exist only
  when their callback does, `progress=None` renders an indeterminate sweep rather
  than a fake percentage, media panels only grow when a thumbnail file really
  exists, and placement is deterministic: candidates are scored for overlap with
  the face, with other panels and with the screen edge.
- **`ui/dynamic_island.py`** — the minimised representation: drag, expand,
  collapse, restore, notification display. A view only; it holds no handle on the
  microphone, audio or the live session.
- **`ui/health_strip.py`** — four live subsystem indicators (letter glyph + real
  detail tooltip; unavailable is hollow, never green) plus an in-HUD toast.
- **Voice-command feedback** — `main.py` wraps real tool execution in
  `begin_command` / `finish_command`, so a command opens a highlighted task panel
  and is only marked COMPLETED when the tool's own result text does not read as a
  failure.
- **`docs/HOLOGRAPHIC_UI_UPGRADE.md`** — what shipped, what is partial, and how to
  run it.
- **`core/failsoft.py`** — the sanctioned way to fail soft without failing
  silently. `failsoft.suppress("<module>:<operation>")` replaces a bare `pass` in
  an `except` handler, records the failure in a bounded, thread-safe table
  (identical failures are counted, not duplicated) and never raises.
  `failsoft.report()` prints what is currently being swallowed, sorted by
  frequency, with the `file:line` of each handler.
  `JARVIS_FAILSOFT_REPORT=1` prints the summary after a pytest run, and
  `JARVIS_FAILSOFT_LOG=1` emits a warning per suppression at runtime.

- `docs/DEVELOPMENT.md` — setup, test, lint and CI workflow for contributors,
  including the current lint-debt table and a ratchet plan.
- `requirements-dev.txt` — test/lint tooling separated from the runtime
  dependency set, so a user install never pulls pytest or ruff.
- `JarvisAI/conftest.py` — one place that puts the app's roots on `sys.path`, so
  the test suite runs from any working directory, plus graceful skipping of the
  four GUI test modules when Qt's system libraries (`libGL`, `libEGL`) are not
  installed.
- `pyproject.toml` — pytest configuration (test paths, markers), ruff
  configuration (the CI lint gate) and coverage configuration, so all tooling
  reads one file.
- `.pre-commit-config.yaml`, `.editorconfig`, `.gitattributes` — consistent
  whitespace, line endings and YAML/TOML/JSON validity before a commit lands,
  with Windows `.bat` files kept on CRLF.
- `tests/test_project_health.py` — guards against the `config` import collision
  coming back, against the two `requirements.txt` copies drifting apart, against
  dev-only packages leaking into the runtime dependency list, and (new) walks
  the internal import graph so a name removed from one module cannot silently
  break an importer.
- `tests/test_ui_import_smoke.py` — imports every `JarvisAI/ui/` module once
  (skipped where Qt cannot load) so a broken panel import fails CI.
- `memory.prospective_memory.pending_intentions()` — active intentions ordered
  soonest-first, for the scheduler panel and any future planner UI.
- CI: a dedicated fast `lint` job, broader path filters (root launchers,
  packaging files, `voice/`, `scripts/`), dependency caching across both
  requirement files, and cancellation of superseded runs.

### Fixed

- **The hologram sat in a black rectangle.** Both renderers cleared to
  `transparent`, which Qt composites as black on a plain child widget. They now
  clear to `hologram_theme.BACKDROP_RGB`, the same colour the window paints, and
  the stage/stack no longer paint an opaque background.
- **The status strip was clipped.** Four indicators needed 206 px but the widget
  asked for 150, so the AI-session indicator was cut off.
- **A finished task panel could crash the HUD.** Archiving ran from a
  `QTimer.singleShot` whose context outlived the window; PyQt aborts the process
  when an exception escapes a slot, so the timer is now parented to the window and
  every status/timer slot is exception-proof.
- **Playback could lose barge-in protection.** In `core/audio_playback.py` the
  viseme/HUD work and the echo-guard bookkeeping shared one `try` block, and the
  level came from a bare `max()` over the viseme schedule. An empty schedule
  raised `ValueError`, which skipped `echo.note_output()` — so the echo guard
  never learned what JARVIS was playing, and JARVIS could hear its own reply and
  interrupt itself. The level now comes from `viseme_peak_level()`, which
  returns `None` for an empty schedule and falls back to the PCM level, and the
  echo update has its own guard so it can no longer be skipped by cosmetic code.
  Found by running the test suite with `JARVIS_FAILSOFT_REPORT=1`.

- **Memory panel always showed zero facts.** `MemoryPanel.fetch_real_memory_state()`
  imported `get_memory_manager` and called `get_all_facts()` — neither exists in
  `memory.memory_manager` — inside a bare `try/except`, so the counters stayed at
  zero and nothing reported an error. It now uses `all_entries_for_ui()`.
- **Scheduler panel always showed "No upcoming tasks".** Same pattern:
  `ProspectiveMemory().get_pending_tasks()` was never a real API. A real
  `pending_intentions()` helper was added to `memory/prospective_memory.py`
  (active intentions, soonest time trigger first) and the panel now uses it.
- 110 dead, duplicate or stale imports removed across the app (`ruff F401`/
  `F811`), including an availability-probe block in `open_app.py` and
  `youtube_video.py` that imported `psutil`, `pyautogui` and `numpy` and then
  never read the flag it set.

- **Crash when `config` was resolved to OpenCV's module.** Three action modules
  (`flight_finder`, `game_updater`, `youtube_video`) imported their OS helpers
  from the generic top-level `config` package. `opencv-python` ships its own
  `cv2/config.py` and leaks the `cv2` directory onto `sys.path` while it loads —
  including when its native module fails to load. Once that happened, those
  modules raised `NameError: name 'LOADER_DIR' is not defined` and the app died
  on a message that pointed nowhere near the cause. The helpers now live in
  `core/host_env.py`, which no third-party wheel claims;
  `config/__init__.py` re-exports them so existing extensions keep working.
- **`NameError` in the playback fallback path.** `core/audio_playback.py` called
  `_output_write_is_unpaced()` without importing it, so the "endpoint is not
  pacing audio" recovery branch could crash instead of switching speakers. This
  is the first bug the new ruff gate would have caught.
- Test collection aborted entirely on Linux machines without `libGL`, hiding
  ~400 passing tests. Those four modules are now excluded with a notice in the
  pytest header, and the camera-failure test skips with an explanatory reason
  once OpenCV cannot load.

### Changed

- **Screen capture no longer round-trips through PNG**
  (`JarvisAI/actions/screen_processor.py`): raw screen pixels go straight to the
  JPEG that is sent. Same bytes, 251 ms → 26 ms per synthetic 1920×1080 frame; the
  intermediate PNG buffer is gone. Falls back to the old path if PIL is missing or
  the direct encode fails.
- **OpenCV is imported on first camera use** instead of at startup; screen capture
  never needed it.
- Every silent `except: pass` / `except: continue` handler in the app now records
  through `core.failsoft.suppress()`: **177 `pass` sites and 25 `continue` sites**
  across 60 files, renamed to the subsystem they belong to (for example
  `core.audio_playback:note_output`, `dashboard.server:<module>`).
- The lint gate now also enforces `S110` (try-except-pass) and `S112`
  (try-except-continue), so a new silent handler fails the build instead of
  joining 950 invisible ones.
- `docs/DEVELOPMENT.md` gained a "Failing soft without failing silently" section:
  the decision table for when to swallow, when to log, and when to let the error
  through, plus how to read the suppression report.

- The lint gate now also enforces `F401` (unused import) and `F811` (shadowed
  redefinition) — zero findings across the codebase, with the three intentional
  re-exports marked `# noqa: F401` and explained in place.
- New `tests/test_ui_import_smoke.py` imports every UI module (skipped where Qt
  cannot load) so a broken import in a panel fails CI rather than a user's
  window. It runs in the Windows smoke job.
- `tests/test_project_health.py` gained a static import-graph check: every
  `from <internal module> import <name>` must resolve to something that module
  actually defines. It immediately found the two dead panel APIs above.
- CI's Ubuntu job installs `libgl1` alongside `libegl1`, so the Qt tests run
  there instead of being skipped.

- `pyproject.toml` gained project metadata (keywords, classifiers, project URLs)
  so the package describes itself on PyPI-style indexes.
- CI installs test dependencies from `requirements-dev.txt` instead of pinning a
  bare `pytest`.
